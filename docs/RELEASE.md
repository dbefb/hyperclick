# 发布清单

此清单是 Hyperclick 的项目规范，不是 Hyperliquid 官方认证标准。

## 本次包的状态

0.7.3 更新图标、显示名称和文档，未增加支付、统计或新的交易权限。附带可加载扩展与对应源码。真实 OKX / OneKey 本版验收和独立安全审计未完成，不能把开发预览包当作已审计正式版宣传。

## GitHub 公开之前

- 选择并添加真实 `LICENSE`，补齐版权主体，更新 `package.json` 的许可字段。当前 `UNLICENSED` 不能宣传为开放源代码许可。
- 填写维护者、支持渠道及私密漏洞报告渠道；验证渠道能收到信息。
- 清理私钥、活跃签名、会话数据和个人日志。提交锁文件与第三方许可，排除 `node_modules/` 和本地缓存。
- README 写清安装、版本、支持范围、数据去向、已知限制；不要使用“官方”“绝对安全”“覆盖全部功能”等未验证承诺。
- 发布 tag 对应具体源码提交、预编译扩展 ZIP、更新说明、SHA-256 校验文件。校验值证明文件一致性，不替代可信发布渠道或安全审计。

## 商店提交之前

- 主渠道先选 Chrome Web Store，稳定后再考虑 Edge Add-ons。创建开发者账户并遵守适用条款。
- 商店上传包根目录必须直接包含 `manifest.json`；不能把整个源码发布包作为扩展 ZIP 上传。
- 准备图标、真实操作截图、简短演示、支持 URL、公开隐私政策 URL、权限用途说明，以及不包含真实凭据的审核操作说明。
- 如收费，明确哪些功能收费、价格、退款/取消规则和支付主体；隐私政策同步反映外部支付及许可校验的数据流。
- 所有可执行代码随扩展打包。不得靠远程下载代码实现更新，也不要用代码混淆冒充付费防护。
- 实测干净安装、升级、首次连接、两种钱包混签、拒签、切号、过期、网络中断和未知提交结果。

## 验收记录格式

每次记录：日期、版本/tag、扩展 ID、浏览器版本、钱包版本、网络、动作、测试账户类型、复现步骤、预期结果、实际结果、状态、脱敏证据。状态只用「通过」「失败」「未执行」；对原网页 UI 与直接 API 分开记录。

功能表分列「已适配」「SDK 对照」「模拟端到端」「真实钱包」「节点结果」。不能用一个总勾选掩盖验证层级差异。

## 维护安排

公布支持范围和尽力而为的响应方式，不承诺单人无法兑现的 24 小时 SLA。关注官方 API 公告；协议变化时先停止受影响入口，验证后发布修复。保留源码版本和发布说明供用户核对。
