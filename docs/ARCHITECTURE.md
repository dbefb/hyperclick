# 架构与信任边界

适用版本：0.7.3。本文说明扩展的组成与数据流，不构成安全审计结论。

## 组件职责

| 组件 | 位置 | 职责 |
| --- | --- | --- |
| 网页适配层 | `page.ts`、`transport.ts`、`x-provider.ts` | 在指定官方网页注入连接入口；保持网页账户 M；识别 HTTP / WebSocket 操作请求 |
| 消息桥 | `content.ts` | 在网页和扩展间传递受校验的消息 |
| 协调后台 | `background.ts` | 查询成员和阈值、存储提案、核验签名与上下文、提交及回传结果 |
| 协议编码 | `actions.ts`、`core.ts` | 动作白名单、类型校验、两类内层签名及最终外层封装 |
| 用户界面 | `home.ts`、`ui.ts`、`panel.ts` | 连接入口、账户列表、内容核对、提交人选择及签名收集 |
| 原生钱包 | OKX / OneKey 扩展 | 保管密钥、展示签署请求、由用户批准并执行签名 |

## 一次操作的数据流

原网页构造操作，M 或已授权网页交易代理完成初始签名。Hyperclick 捕获支持的请求，校验来源、网络和初始签名；代理请求还需验证代理归属。后台读取 HyperCore 多签配置，界面展示待签内容。用户选择提交人，各成员签署绑定 M、提交人及操作的内容。达到阈值后，提交人签署最终封装，后台再核对配置、时效和原网页状态，向官方 API 提交，并回传节点真实响应。

提交人不因被选中而得到新的资产权限。其作用是参与协议要求的最终封装签名与提交；成员签名和最终签名是两个不同阶段。改变提交人会使既有成员签名不可继续用于原提案。

## 身份保持与限制

网页通过 Hyperclick 提供的账户入口使用 M；真实钱包可以在授权成员之间切换。隔离不等于钱包同时选中了所有账户。下一次由 M 发起的初始签名仍可能要求原连接钱包切回 M，组件会提示，不能代替用户强制切号。

Hyperclick 只适配明确支持的 HyperCore 操作，不是任意 EVM 请求的通用多签转换器。交易代理授权还可能允许代理在协议授权范围内进行后续操作；多签协调工具不会自动把代理所有行为变成逐笔人工审批。

## 信任边界

- 不持有私钥，不代表没有安全风险：扩展可读取和处理请求、地址及可执行授权的签名；恶意更新或编码错误仍可能造成损失。
- 提案展示必须与真正签署的数据一致。测试覆盖一致性，但未经过第三方独立审计。
- 钱包来源标识通常反映请求所在网页，不构成对 Hyperclick 的安全认证。本扩展未获得钱包方或 Hyperliquid 的安全认证。
- 页面消息、钱包返回值和网络返回值均应当作不可信输入。新增动作必须增加结构校验及签名对照，不允许通用盲签兜底。
- 只申请官方应用/API 域名权限。生产包不加载远程可执行脚本；依赖和第三方许可随构建打包。
- 取消及校验失败不回退原单签。超时、后台重启等造成提交结果未知时，保留未知状态，不自动重发。

## 尚待验证

真实钱包版本差异、原网页更新、动作的当前协议权限、连接隔离边缘行为及异常响应。具体逐项验收见[测试清单](../ACCEPTANCE.md)；不能用自动化通过代替真实钱包验收。
