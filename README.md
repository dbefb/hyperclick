# Hyperclick 0.7.3

面向 HyperCore 原生多签账户的本地浏览器扩展。原网页发起操作，Hyperclick 核对请求、协调成员签名、让提交人最终签署，并直接提交 HyperCore。

独立开发项目，与 Hyperliquid、OKX、OneKey 无隶属或官方背书关系。当前是开发预览版，未经过独立安全审计；操作适配数量不代表全部通过真实钱包验收。

[下载安装包](https://github.com/dbefb/hyperclick/releases) · [English](README.en.md)

## 安装与升级

从 Releases 下载 `Hyperclick-v0.7.3-extension.zip`。GitHub 自动生成的 Source code 包需要先构建，不能直接安装。

1. 解压安装包，在 Chrome 或 Edge 的扩展管理页面开启开发者模式。
2. 选择「加载已解压的扩展程序」，选择安装包解压后包含 `manifest.json` 的文件夹；替换原目录时，点击原扩展的刷新按钮。不要同时启用新旧两份扩展。
3. 关闭旧侧栏，刷新 Hyperliquid 标签页。断开旧连接，在原网页的钱包列表重新选择 **Hyperclick**。
4. 侧栏选择 OKX Wallet 或 OneKey，并在该钱包内确认多签账户 M。
5. 在 Hyperliquid 发起操作。原网页的首次确认完成后，侧栏依次显示「核对操作 → 选择提交人 → 多签收集」。已授权的网页交易代理发起请求时，组件核对代理与 M 的链上关系。
6. 成员可混用 OKX 和 OneKey。达到阈值后，切换至提交人的钱包，完成最终签名。真实节点响应回传原网页，成功后侧栏返回主界面。

无需运行本地服务器。无需导入私钥、助记词。钱包自己的连接及签名确认仍在 OKX / OneKey 内完成。

## 完成后继续操作

网页保持连接多签账户 M，真实钱包可能仍选中刚完成签署的成员。首页会显示原连接钱包、当前账户和下一次首次签名需要的 M 地址。若不一致，提示在原钱包切回 M；切回后自动更新为可继续操作，无需断开重连。若已点击原网页操作但因账户不一致被阻止，网页会出现明确提示，切回后重新点击即可。

本版不强制切换钱包账户，也不自动重放此前失败的操作。

## 协作范围

当前仅支持同一台电脑、同一浏览器内签署，不支持异地设备间的签名同步。

## 本版范围

接入 47 种明确识别的 HyperCore 操作：代理授权、转账、提现、质押、金库、子账户、订单、杠杆与保证金、多签配置、账户设置等。完整编号和验证范围见 `COVERAGE.md`。

该数字表示实现了请求适配、展示、两层多签编码和提交回传，不表示 47 个原生网页入口均已通过真实钱包实机验收。最终仍由 HyperCore 检查账户权限和协议条件。

普通 Arbitrum 入金交易、HyperEVM 合约调用、部署者及验证者管理等不在本版范围；未知操作在 Hyperclick 连接模式下会停止处理。

## 数据与运行方式

- 地址、待签请求、签名及流程状态保存在当前浏览器的扩展会话存储中，不上传维护者服务器。
- 钱包接口负责签名，扩展恢复并校验签名者；不读取钱包或网页交易代理的私钥。
- 通过官方 `/info` 查询成员、阈值和代理关系，通过官方 `/exchange` 提交最终多签。
- 原网页通过 Hyperclick 保持 M，成员在真实钱包中切换不会改变本次提案所属账户。
- 操作、网络、随机数，以及适用的金库/子账户上下文和失效时间均绑定到签名。
- 取消或校验失败不回退发送原始单签；结果未知不自动重发，需核对实际状态。

## 开发

源码位于本仓库根目录。Node.js 20 或更新版本下执行：

```sh
npm ci
npm run typecheck
npm test
npm run build
```

构建结果在 `dist/`。`npm run demo` 仅运行模拟钱包交互演示，生产扩展不依赖该本地服务。第三方许可原文见 `THIRD_PARTY_NOTICES.txt`。测试记录见 `VALIDATION.md`，真实钱包验收步骤见 `ACCEPTANCE.md`。
